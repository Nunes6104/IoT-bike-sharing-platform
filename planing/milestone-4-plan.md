# Milestone 4: Secure replay, ingestion, and historical dashboard

## Problem and approach

Deliver an incremental end-to-end Stage 2 MQTT replay feeding the same persistent event store as Stage 1, plus the requested Stage 1 historical analytics in an authenticated Node-RED dashboard. Reuse validation and storage where safe, repairing the existing persistence and TLS prerequisites before relying on them. Keep the five cloud services separate; Client 1 remains a separate publisher. ML clustering and advanced Stage 2 cluster visualizations remain outside this milestone.

## Confirmed decisions

- Scope includes MQTT replay, online processing, historical analytics, and the dashboard.
- Dashboard uses Node-RED and a processor-hosted analytics API, with TLS and server certificate verification on the service link, authentication and least-privilege access.
- Fare assumption: use exact fractional minutes for the e-bike surcharge; round positive overage duration up to whole minutes. Member classic has 45 included minutes and $0.20 per additional minute; casual classic has a $4.50 base, 30 included minutes and $0.30 per additional minute. The e-bike surcharge is $0.25/minute for members and $0.35/minute for casual users on all exact trip minutes. Use precise decimal arithmetic and explicitly document final-cent rounding and its chosen tie rule before implementation.
- Publisher recovery uses a durable checkpoint, with file identity and replay configuration validation; replay speed scales original inter-message intervals.
- Upon implementation, create repository folder `planing`, move the preserved previous Milestone 3 plan from the session workspace into it, and save this Milestone 4 plan there. No other previous plan files were found in the repository or current session. If preserving a session file by moving risks loss, copy and verify it before removing its source; do not reconstruct an unavailable plan.

## Current evidence and prerequisites

- `docker-compose.yml` runs the processor as `infrastructure/placeholder.py`; ML remains a placeholder. Node-RED has TLS/authenticated settings but no dashboard flows. Mosquitto explicitly enables TLS on port 1883 and uses group-scoped ACLs.

Its SQLite station write is MySQL-specific. `processor/db.py` creates an SSL context after connection but does not pass it to the driver, and its schema splitting skips statements beginning with comments. These are implementation findings, not assumed capabilities: fix and test them as prerequisites.

The local dataset script uses SQLite, is not a unittest test case, and does not prove a real MySQL import. Revalidate actual behavior and correct affected documentation.
- Real Stage 2 samples include `seq`, `type`, `ts`, `ride_id`, `rideable_type`, `member_casual`, `duration_s`, station fields and coordinates; do not use fabricated example payloads or assume any uninspected fields. Validation already defines the three observed event categories.

## Acceptance criteria and notes

- TLS certificate and hostname verification works on MQTT, MySQL, Node-RED browser access and the processor API; invalid certificates and plaintext are rejected where applicable. No secrets committed or placed in logs.
- Interrupted replay resumes at its durable checkpoint with original timing scaled by the configured multiplier; disconnects and retries cannot silently drop a committed or quarantined event. Explicitly document residual broker persistence limitations.
- Re-import and redelivery preserve one event per dataset sequence. Conflicting content is retained for audit without overwriting the original. Database or quarantine failures are observable and do not produce success-shaped acknowledgments.
- Dashboard offers configurable local-time ranges and accurate requested hourly/daily/weekly trends, energy, duration, time-of-day, fare and segmented station-utilization views with coverage indicators and empty/full observations.
- Supplied Stage 1 and Stage 2 data are reflected in the same analytics after verified ingestion. Edge cases include trips spanning stages, missing coordinates/stations, short/long rides and gaps in station updates.
- Tests and actual integration results are reported honestly, including any unavailable Docker or certificate prerequisites. ML training and cluster evolution are deferred.
