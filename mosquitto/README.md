# Mosquitto MQTT Broker

This directory contains configuration and certificate setup for the Eclipse Mosquitto MQTT broker, which serves as the message bus for all IoT communication between docking stations (emulated by Client 1) and the cloud processing platform.

## Purpose

Mosquitto receives MQTT messages from the publisher client (replaying station events), routes them to the subscriber service, and enforces topic-based access control. All communication is secured with TLS certificates to satisfy the project security requirement.

## Contents

### Configuration

- **`mosquitto.conf`** — Main broker configuration
  - Listeners: TLS on port 8883 (standard MQTT over TLS) and plaintext on port 1883 for internal Docker communication
  - Certificate paths: `/mosquitto/config/certs/server.crt`, `/mosquitto/config/certs/server.key`, `/mosquitto/config/certs/ca.crt`
  - Authentication: username/password file at `/mosquitto/config/passwd`
  - Topic ACLs: `/mosquitto/config/acl` (read/write permissions per user/topic)
  - Persistence: enabled in `/mosquitto/data/`
  - Log level: informational

### Certificates and credentials

- **`certs/`** — TLS certificate directory (generated by infrastructure/setup_local.py)
  - `server.crt` — Server certificate (signed by CA)
  - `server.key` — Server private key (must be protected)
  - `ca.crt` — CA certificate (used by clients to verify server identity)
  - Certificates are generated fresh on each setup; never commit them to git

- **`passwd`** — Username/password file (generated by infrastructure/setup_local.py)
  - Format: `username:hashed_password` (bcrypt hash)
  - Contains credentials for publisher and subscriber services
  - Regenerated on setup; never commit to git

- **`acl`** — Topic access control list (generated by infrastructure/setup_local.py)
  - Defines which users can subscribe/publish to which topics
  - Format: `user <username>` followed by `topic (read|write|readwrite) <pattern>`
  - Publisher writes to `idc/fcXX/status/<station_id>`, `idc/fcXX/trips/started`, `idc/fcXX/trips/ended`
  - Subscriber reads all topics under `idc/fcXX/`
  - `XX` is the actual group number (from Docker Compose environment)

## Usage

### Docker Compose integration

The `mosquitto` service is defined in `docker-compose.yml`:

```yaml
mosquitto:
  image: eclipse-mosquitto:latest
  ports:
    - "8883:8883"  # TLS MQTT (external)
    - "1883:1883"  # plaintext MQTT (internal Docker)
  volumes:
    - ./mosquitto/mosquitto.conf:/mosquitto/config/mosquitto.conf
    - ./mosquitto/certs:/mosquitto/config/certs
    - ./mosquitto/passwd:/mosquitto/config/passwd
    - ./mosquitto/acl:/mosquitto/config/acl
    - mosquitto_data:/mosquitto/data
  healthcheck:
    test: ["CMD", "mosquitto_sub", "-h", "mosquitto", "-p", "1883", "-t", "\\$SYS/broker/uptime"]
    interval: 10s
    timeout: 5s
```

### Certificate generation

Certificates are created by the infrastructure setup script:

```powershell
python infrastructure/setup_local.py --group-number 10
```

This generates:
- CA certificate and key
- Server certificate and key (CN=mosquitto)
- Password file with users: `publisher`, `subscriber`
- ACL file with appropriate topic permissions

### Manual broker commands

Start broker (outside Docker):
```bash
mosquitto -c mosquitto/mosquitto.conf
```

Publish test message (requires TLS certificate):
```bash
mosquitto_pub -h localhost -p 8883 \
  --cafile mosquitto/certs/ca.crt \
  -u publisher -P <password> \
  -t "idc/fc10/status/JC115" \
  -m '{"type":"station_status","ts":"2024-03-20T14:30:00-04:00","station_id":"JC115","bikes_available":5,"docks_available":10}'
```

Subscribe to all events (requires TLS certificate):
```bash
mosquitto_sub -h localhost -p 8883 \
  --cafile mosquitto/certs/ca.crt \
  -u subscriber -P <password> \
  -t "idc/fc10/#"
```

## TLS configuration notes

### Port choices

- **8883** — Standard MQTT over TLS (mTLS capable, common for production)
  - Used by publisher and subscriber when connecting from outside the Docker network
  - Requires CA certificate validation on client side
  - Configured in `mosquitto.conf` with `listener 8883`

- **1883** — Plaintext MQTT (internal Docker bridge)
  - Used for health checks and debugging within the container network
  - Only accessible from containers on the same Docker network
  - Not exposed to host by default; Docker Compose exposes 1883 for testing only

### Certificate validation

- **Server certificate** must have CN (Common Name) or SAN (Subject Alt Name) matching the hostname
  - In Docker: hostname is `mosquitto` (service name in Compose)
  - On localhost: certificate CN is typically `localhost` or the actual hostname
  - Clients validate against `ca.crt` to verify server identity
  - Self-signed CA is acceptable for development/testing; use trusted CA for production

- **Client certificate** (mTLS) — not currently required by Mosquitto config
  - Can be enabled by setting `require_certificate true` in `mosquitto.conf`
  - Would require publisher and subscriber to supply client certificates

## Security best practices

1. **Never commit certificates or passwords to git**
   - `.gitignore` excludes `.local/` directory where certs are stored
   - Regenerate on each deployment

2. **Restrict file permissions** (outside Docker)
   ```bash
   chmod 600 mosquitto/certs/server.key
   chmod 644 mosquitto/certs/server.crt
   chmod 644 mosquitto/certs/ca.crt
   chmod 600 mosquitto/passwd
   chmod 644 mosquitto/acl
   ```

3. **Use strong passwords** for publisher and subscriber accounts
   - Generated by setup script with 16-character random passwords

4. **Rotate credentials periodically**
   - Regenerate certificates and passwords when deploying to new environments
   - Keep separate credentials for dev/staging/production

5. **Restrict MQTT topics**
   - ACL file limits users to their intended topics
   - Publisher cannot read; subscriber cannot write
   - System topics (starting with `$SYS`) require explicit permission

## Troubleshooting

### "Connection refused" on port 8883

Check that Mosquitto is running and listening:
```bash
docker compose logs mosquitto
# Or outside Docker:
netstat -an | findstr 8883
```

### "Certificate verify failed"

Ensure CA certificate is provided and matches the server certificate:
```bash
# Check server certificate
openssl x509 -in mosquitto/certs/server.crt -noout -text

# Verify certificate chain
openssl verify -CAfile mosquitto/certs/ca.crt mosquitto/certs/server.crt
```

### "Authentication failure"

Verify credentials in `passwd` file and ensure ACL allows the topic:
```bash
# Check password entry exists
grep username mosquitto/passwd

# Check ACL rules
grep -A 5 "user publisher" mosquitto/acl
```

### Broker not persisting messages

Check that `persistence true` is set in `mosquitto.conf` and `/mosquitto/data/` is writable by the container.
